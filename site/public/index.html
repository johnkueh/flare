Your apps' backend, on Cloudflare.

Like Firebase, but it's your own Worker. Phones work offline, share data with each other, sign in and report analytics and crashes, from one Rust core on iOS, Android and the web.

Four pieces

Everything an app needs from a server.

Use one or all four. Each is a package you add to your own Worker, with a small Swift and Kotlin side.

Sync

Every phone keeps a full copy in SQLite and writes instantly. Changes sync in the background, and merge without losing anything.

  • Shared spaces with an 8-letter invite code
  • Newest edit wins per field; lists keep their order
  • Live updates and photos in R2
Read SYNC.md →

Auth

Every phone is signed in from its first launch, and proves it's a genuine copy of your app. A real account later keeps everything.

  • Built on Better Auth, stored in D1
  • App Attest and Android key attestation
  • Apple and email codes; cookies for the web
Read AUTH.md →

Flags

List your flags in one JSON file. Cloudflare Flagship serves them, and every platform reads them as typed properties, generated on each build.

  • iOS, Android, web, Node and Rust
  • Works offline; screens don't change mid-use
  • Live kill switches, rollouts per user
Read FLAGS.md →

Analytics and crashes

A Rust SDK queues events on disk and sends them in batches. They land in Iceberg tables you query with SQL. Crashes, hangs and errors come in the same way. No Firebase, no GA4, no Sentry.

  • Survives crashes and days offline
  • Crashes with their stack and the last 30 events
  • Cloudflare Basin; ingest is free

How it works

One core on the phone. Your Worker in the cloud.

The phone never waits on the network. The Worker is yours: your account, your data, your bill.

Your appSwiftUI, Compose or a web page, calling a few plain functions.
SwiftKotlinTS
Rust coreThe local store, the merge rule and the event queue. Same code on every platform.
SQLiteUniFFI
Your WorkerOne Durable Object per space, accounts in D1, photos in R2, events in Basin.
Durable ObjectsD1R2Basin
The same approach as Mozilla. Firefox on iOS and Android shares its sync and telemetry code as Rust components, with Swift and Kotlin generated by UniFFI. Flare is built the same way: write the hard parts once, run them everywhere.
Merges like Figma and Linear. Not a text CRDT like Yjs: each field keeps its newest edit, lists use fractional positions, and folders can't loop. It's the model Figma and Linear use for their data, with one change: edits are ordered by a clock on the phone, so a change made offline keeps its place. How it works →
Flags like LaunchDarkly and Statsig. Each user is evaluated by a stable key, so a 10% rollout keeps the same people, as in LaunchDarkly. Like Statsig's mobile SDKs, the app starts with the values it last saw, and a flag a screen has read doesn't change under the user. The difference: the rules live in Cloudflare Flagship behind your own Worker, and it speaks OpenFeature's OFREP. How it works →

Add it

A few lines on each side.

Pin one tag of this repo on every platform and bump them together.

# Sync, plus accounts and flags if you want them
pnpm add "@sync/server@github:johnkueh/flare#0.5.0&path:/server"
pnpm add "@flare/auth@github:johnkueh/flare#0.5.0&path:/auth"
pnpm add "@flare/flags@github:johnkueh/flare#0.5.0&path:/flags"

// src/index.ts
export { SpaceObject } from "@sync/server/space";
