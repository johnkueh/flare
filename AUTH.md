# Auth

Accounts for apps on Flare, built on [Better Auth](https://www.better-auth.com).
Every phone is signed in from its first launch as an **anonymous user**, and
proves it's a genuine copy of the app with App Attest (iOS) or Android key
attestation. Signing in with a real account later links that user, so
nothing is lost. Web pages sign in with Better Auth's cookie.

| Piece | What it is |
| --- | --- |
| `auth/src/index.ts` | `flareAuth(env, options)`: Better Auth with the anonymous, bearer and attestation plugins on D1. `whoIs` and `authenticate` for your own routes and `spaceHttp`. |
| `auth/src/plugin.ts` | `flareAttest`: key registration, the sign-in challenge, and the gate on anonymous sign-in. Records the signing key as the session's `deviceId`. |
| `auth/src/attest/` | App Attest and Android Keystore verification, ported from Cooked's API. Same `attest_keys` table. |
| `auth/migrations/` | `attest.sql` and `better_auth.sql` (generated by `pnpm gen:migration`). |
| `swift/.../FlareAuth.swift`, `kotlin/.../FlareAuth.kt` | The phone side: registers the key, signs in, keeps the token. It's the `SpaceTokens` a `SpaceClient` takes. |
| `example/` | A shared grocery list: auth, spaces and a web page in one Worker, with end-to-end tests. |

Unlike `server/`, this package has npm dependencies (Better Auth,
`@peculiar/x509`, `cborg`), which is why it lives on its own.

## Using it from a Worker

```sh
pnpm add "@flare/auth@github:johnkueh/flare#<tag>&path:/auth"
```

Apply both files in `auth/migrations/` to the Worker's D1, add the
`nodejs_compat` flag, and set `BETTER_AUTH_SECRET` (a secret),
`BETTER_AUTH_URL`, `APP_ATTEST_APP_IDS`, `ANDROID_APP_IDS` and, while
testing, `APP_ATTEST_ALLOW_DEVELOPMENT=true`. On a simulator or in CI,
`FLARE_AUTH_ALLOW_UNATTESTED=true` lets anonymous sign-in through without
attestation.

```ts
import { authenticate, flareAuth, whoIs } from "@flare/auth";
import { relinkMember } from "@sync/server/spaces";

const auth = flareAuth(env, {
  // An anonymous user signed in to an account: their spaces go with them.
  onLinkAccount: ({ anonymousUserId, userId }) => relinkMember(env, anonymousUserId, userId),
  apple: { appBundleIdentifier: "com.example.app" },
  sendEmailCode: async (email, code) => ctx.waitUntil(sendWithYourMailer(email, code)),
});
if (url.pathname.startsWith("/v1/auth/")) return auth.handler(request);
const space = spaceHttp(request, env, { prefix: "/v1", authenticate: (r) => authenticate(auth, r) });
const who = await whoIs(auth, request.headers); // { userId, deviceId } for your own routes
```

`apple` turns on Sign in with Apple for the ID token a phone gets from
`ASAuthorizationAppleIDProvider` (`POST /v1/auth/sign-in/social`
`{ provider: "apple", idToken: { token, nonce } }`). `sendEmailCode` turns
on 6-digit email codes (`/email-otp/send-verification-otp`, then
`/sign-in/email-otp`). Anything else Better Auth takes goes in
`betterAuth`.

## Spaces and accounts

A space's member is the **user**, not the phone. Pass `whoIs(...).userId`
as the member id to `createSpace`, `joinSpace` and the rest, and the
`deviceId` as `NewDevice.deviceId` (or `spaceInfo`'s `device`) so the
phone or browser is listed under them in `SpaceInfo.devices[].devices`.
`SpaceClient` says which device it is on every request (`X-Device-Platform`,
and `X-Device-Name`, percent-encoded, when it's given a `deviceName`).

- **A new phone** signed in to the same account is already a member of
  everything: no restore step.
- **An anonymous user who signs in** to an account is moved by
  `relinkMember` in `onLinkAccount`. If the account was already in the same
  space, the anonymous member just leaves it.
- **Which spaces a user is in** is the `space_members` table in D1
  (`server/migrations/space_members.sql`), kept by `createSpace`,
  `joinSpace`, `leaveSpace` and `removeDevice`.
- **An app from before accounts**, whose members are device ids, moves them
  with `relinkSpaces(env, spaceIds, deviceId, userId)` once the device has
  signed in.

## Signing in from a phone

1. Once per install: `GET /v1/auth/attest/challenge`, attest a new key with
   that challenge, then `POST /v1/auth/attest/apple` `{ keyId, attestation, challenge }`
   (or `/attest/android` `{ keyId, certificateChain, challenge }`).
2. Each sign-in: get a fresh challenge, sign its UTF-8 bytes with the key
   (an App Attest assertion, or the Android signature over
   `SHA256(challenge) ‖ counter`), and send it with `X-Attest-Challenge`
   plus the usual `X-App-Attest-*` or `X-Android-*` headers.
   `POST /v1/auth/sign-in/anonymous` needs them; other sign-ins and
   sign-ups take them, so the new session keeps the device.
3. Keep the `set-auth-token` response header in the Keychain (or Android's
   private storage) and send it as `Authorization: Bearer <token>`.

A 401 with `ATTESTATION_REQUIRED` means sign in again; `INVALID_ASSERTION`
means the signature didn't check out (a used challenge, a counter that
didn't go up).

## From an app

`FlareAuth` does all of that and is the `SpaceTokens` a `SpaceClient`
takes. It signs in anonymously the first time a request needs a token.

```swift
let auth = FlareAuth(baseURL: URL(string: "https://api.example.com/v1/auth")!)
let client = SpaceClient(baseURL: URL(string: "https://api.example.com/v1")!, tokens: auth)
try await auth.signInWithApple(idToken: idToken, nonce: nonce)   // links the anonymous user
```

```kotlin
val auth = FlareAuth(context, "https://api.example.com/v1/auth")
val client = SpaceClient("https://api.example.com/v1", tokens = auth)
auth.signInWithEmailCode(email, code)   // after auth.sendEmailCode(email)
```

On the simulator `FlareAuth` skips App Attest by itself; on the emulator
pass `allowUnattested = true`. Either needs `FLARE_AUTH_ALLOW_UNATTESTED`
on the server. Android keeps the token in the app's private preferences,
not encrypted storage, so as not to depend on androidx.security.

## Try it: the example

`example/` is a shared grocery list. One Worker serves auth, the spaces
and a web page, and `example/ios` and `example/android` are the same list
as apps. Email codes go to `/dev/outbox` instead of an inbox while
`DEV_OUTBOX` is on.

```sh
cd example
pnpm install
cp .dev.vars.example .dev.vars
pnpm db:local && pnpm dev   # http://localhost:8787
pnpm test                   # the Worker: sign-in, sharing, linking, a second phone
pnpm e2e                    # two people in Chromium: sign in, share, live updates
```

### Phones

Both apps sign in anonymously on first launch (`FlareAuth`), keep each list
in the Rust store and sync it with `SyncPass` and `LiveSocket`. They write
the same `groceries` documents as the web page, so a list open in all three
stays level. Signing in with an email code moves the phone's lists to that
account. Start the Worker (`pnpm dev`) first.

```sh
# iOS simulator: talks to http://localhost:8787. Needs XcodeGen (brew install xcodegen).
cd example/ios
xcodegen
xcodebuild -project Groceries.xcodeproj -scheme Groceries \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath build build
xcrun simctl install booted build/Build/Products/Debug-iphonesimulator/Groceries.app
xcrun simctl launch booted com.johnkueh.flare.groceries

# Android emulator: talks to http://10.0.2.2:8787, the emulator's name for the Mac.
./gradlew -p example/android :app:installDebug     # from the repo root
adb shell am start -n com.johnkueh.flare.groceries/.MainActivity

curl 'http://localhost:8787/dev/outbox?email=you@example.com'   # the code a phone asked for
```

For another server, launch the iOS app with `-server https://…` or build
the Android one with `-Pserver=https://…`. Neither attests on a simulator
or emulator, so the server needs `FLARE_AUTH_ALLOW_UNATTESTED=true`.
